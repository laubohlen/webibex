**Correction (2026-07-23) — the packages are not actually removed:** `easy-thumbnails==2.10` pulls in `svglib`/`reportlab` as a **non-optional** transitive dependency (not gated behind an `[svg]` extra as originally assumed). The resolver re-installed them anyway, just at newer, wheel-having versions: `svglib==2.0.2`, `reportlab==5.0.0`, `cssselect2==0.9.0`, `tinycss2==1.5.1`, `webencodings==0.5.1`. What this change actually did was drop the **broken exact pins** (`1.5.1`/`4.3.1`, no mutual wheel-compatible combination) and let the resolver pick a working combination instead. The functional claim below (SVG-thumbnail code path unreachable) still holds and is why this is safe — but "removed as dead weight" was not accurate; "unpinned so the resolver can satisfy `easy-thumbnails`'s real dependency" is.

**Do NOT:**

If SVG uploads are still denied there, the SVG-rendering code path stays unreachable regardless of which `svglib`/`reportlab` version is installed — the fix is to leave the resolver unconstrained, not to re-pin.
- Assume this fix applies to the RunPod side. It doesn't — `svglib`/`reportlab` never appeared in any RunPod tree (training `dockerfiles/` or inference `builder/requirements.txt`); this is a Railway/Django-app-only dependency file. See the tree-separation table in the session notes.

**Trigger:** any future `pip install`/resolver failure mentioning `svglib` or `reportlab` in this repo; or any change to `FILER_ADD_FILE_VALIDATORS` / SVG upload handling that would make SVG-thumbnail rendering reachable again (worth re-checking the installed versions still satisfy `easy-thumbnails` cleanly at that point).

**Why:** `svglib==1.5.1` (the originally pinned version) has no PyPI wheel (sdist only); the only wheel-having versions (`1.6.0`, `2.0.2+`) require `reportlab>=4.4.3`, but `reportlab` was exact-pinned at `4.3.1` — unsatisfiable under a wheels-only ("no arbitrary code execution at install time") policy. Both packages back `easy-thumbnails`'s SVG-thumbnail rendering for `django-filer` uploads, and that code path is unreachable: SVG uploads are denied outright at `webibex/settings.py:224`. Repo-wide grep confirmed zero app-code references to either package. Dropping the exact pins lets the resolver satisfy `easy-thumbnails`'s real dependency with current, wheel-having versions instead of the broken originals.
